# Деплой бота на сервер

Пошаговая инструкция: от «есть код на GitHub» до «бот отвечает в Telegram и им
можно пользоваться». Рассчитана на то, что вы делаете это впервые.

Бот работает через **polling** (сам спрашивает у Telegram новые сообщения), а
не через webhook — поэтому **домен и SSL-сертификат не нужны**. Нужен просто
сервер с доступом в интернет и Docker.

---

## Что понадобится перед началом

- [ ] Аккаунт в Telegram (для создания бота через @BotFather)
- [ ] Сервер (VPS) — см. Шаг 3
- [ ] Ключ Wildberries Seller API (`WB_API_KEY`)
- [ ] `OZON_CLIENT_ID` и `OZON_API_KEY` из кабинета Ozon
- [ ] Ключ Anthropic (`ANTHROPIC_API_KEY`) — для генерации текста карточек
- [ ] 20–30 минут свободного времени

---

## Шаг 1. Создать бота в Telegram через @BotFather

1. В Telegram найдите **@BotFather** (официальный бот, у него синяя галочка) и
   откройте с ним чат.
2. Отправьте `/newbot`.
3. Введите имя бота (то, что будет отображаться, например «ALICARTUNING
   Manager»).
4. Введите username бота — должен быть уникальным и заканчиваться на `bot`
   (например `alicartuning_manager_bot`).
5. BotFather пришлёт **токен** вида `123456789:AAH...` — это `TELEGRAM_BOT_TOKEN`.
   **Никому его не показывайте** — с этим токеном можно полностью управлять
   ботом от вашего имени.

Дополнительно (необязательно, но приятно): командой `/setdescription`,
`/setabouttext`, `/setuserpic` в BotFather можно задать описание и аватар бота.

## Шаг 2. Узнать свой Telegram ID

Бот отвечает **только** пользователям из списка `TELEGRAM_ADMIN_IDS` (это
специально сделано в целях безопасности — иначе им сможет пользоваться кто
угодно). Чтобы узнать свой числовой ID:

1. Найдите в Telegram бота **@userinfobot** (или @getmyid_bot).
2. Отправьте ему любое сообщение — он пришлёт в ответ ваш ID (число, например
   `123456789`).
3. Если ботом будут пользоваться несколько человек — узнайте ID каждого таким
   же способом.

## Шаг 3. Арендовать сервер (VPS)

Минимальные требования: **2 ГБ RAM, 1–2 ядра, 20+ ГБ диска, Ubuntu 22.04
LTS** (бот лёгкий — Postgres + Redis + Python-контейнеры, больше не нужно).

Домен не нужен — оплатите просто VPS с публичным IP. Варианты (выбирайте по
удобству оплаты):

- **Российские** (оплата российской картой, юрлицом): Timeweb Cloud, Selectel,
  Cloud.ru (VK Cloud), Yandex Cloud.
- **Зарубежные** (нужна карта, принимаемая провайдером): Hetzner,
  DigitalOcean, Vultr.

После оплаты провайдер пришлёт вам **IP-адрес сервера** и **root-пароль** (или
попросит загрузить SSH-ключ — тоже подойдёт).

## Шаг 4. Подключиться к серверу и поставить Docker

Подключитесь по SSH (на Windows — через PuTTY или Windows Terminal, на
Mac/Linux — через обычный терминал):

```bash
ssh root@ВАШ_IP_АДРЕС
```

Введите пароль, который прислал провайдер. Дальше — команды **на сервере**:

```bash
# обновить систему
apt update && apt upgrade -y

# поставить Docker (официальный скрипт)
curl -fsSL https://get.docker.com | sh

# поставить git
apt install -y git

# проверить, что всё встало
docker --version
docker compose version
```

## Шаг 5. Скачать код бота на сервер

Проще всего — через `git clone`. Репозиторий приватный, поэтому нужен
Personal Access Token с GitHub:

1. На GitHub: аватар справа вверху → **Settings** → **Developer settings** →
   **Personal access tokens** → **Tokens (classic)** → **Generate new token**.
2. Дайте право `repo` (полный доступ к приватным репозиториям), срок действия
   — например, 90 дней.
3. Скопируйте токен (он показывается один раз).

На сервере:

```bash
git clone https://ВАШ_ТОКЕН@github.com/filippovden/alicartuning-mp-bot.git
cd alicartuning-mp-bot
```

(Замените `ВАШ_ТОКЕН` на скопированный токен. Ветка `main` теперь содержит
весь код бота.)

## Шаг 6. Настроить `.env`

```bash
cp .env.example .env
nano .env
```

(`nano` — простой текстовый редактор в терминале: стрелками двигаетесь,
печатаете как обычно, `Ctrl+O` затем `Enter` — сохранить, `Ctrl+X` — выйти.)

Обязательно заполните:

| Переменная | Что вписать |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из Шага 1 |
| `TELEGRAM_ADMIN_IDS` | ваш ID из Шага 2 (через запятую, если несколько людей: `123456789,987654321`) |
| `API_AUTH_TOKEN` | случайная строка — выполните на сервере `openssl rand -hex 32` и вставьте результат |
| `WB_API_KEY` | ключ Wildberries Seller API |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | из кабинета Ozon |
| `ANTHROPIC_API_KEY` | ключ Anthropic — тексты карточек (название, описание, буллеты) и быстрый парсинг описания. Пусто — бот всё равно работает: тексты собираются из полей товара без AI, инфографика тоже работает (см. ниже) |
| `XAI_API_KEY` | ключ xAI (Grok Imagine) — AI-инфографика по фото товара. Пусто — инфографика рисуется через Pillow (фото товара + текст буллетов на фирменном фоне), бот живой |
| `STORAGE_BACKEND=s3` + `S3_ENDPOINT_URL`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | **обязательно, чтобы фото попадали в карточку на Wildberries** — см. пояснение ниже |
| `ADMIN_PANEL_PASSWORD` | придумайте пароль, если хотите пользоваться веб-админкой на `/admin` (см. Шаг 8) |

Остальные переменные (`DATABASE_URL`, `REDIS_URL` и т.д.) можно оставить как
есть — они уже настроены на работу внутри docker-compose.

⚠️ **Если оставить `TELEGRAM_ADMIN_IDS` или `API_AUTH_TOKEN` пустыми — это не
баг**: бот и backend откажут всем, пока их не заполнить. Это защита по
умолчанию.

⚠️ **Без S3 (`STORAGE_BACKEND=s3` не задан) карточка на Wildberries создаётся,
но остаётся БЕЗ ФОТО.** WB грузит картинки по публичной ссылке — если фото
лежит только локально в контейнере, площадка до него не достучится. Бот в
этом случае честно пишет «фото не ушли — нужен S3» вместо того, чтобы
молчать или врать про успех. AI-инфографика по фото товара через xAI тоже
скачивает референс по ссылке — без S3 недоступна, но обычный Pillow-рендер
(фото товара с диска + текст) всё равно соберёт картинку и покажет её в
чате — просто на саму карточку WB она не попадёт, пока не настроен S3.

## Шаг 7. Запустить

```bash
docker compose up -d --build
```

Флаг `-d` — запуск в фоне (можно закрыть SSH-сессию, бот продолжит работать).
Первый запуск соберёт образы и накатит миграции БД — займёт пару минут.

Проверьте, что все 6 контейнеров запущены и не падают:

```bash
docker compose ps
```

Все должны быть в статусе `running` (или `healthy` для postgres). Если
какой-то в статусе `restarting` — см. раздел «Если что-то не работает» ниже.

## Шаг 8. Проверить, что бот работает

1. В Telegram найдите вашего бота по username (из Шага 1) и откройте чат.
2. Отправьте `/start` — бот должен поприветствовать. Если молчит — проверьте,
   что ваш ID действительно в `TELEGRAM_ADMIN_IDS` (Шаг 2 и 6).
3. Отправьте `/synccategories` — подтянет дерево категорий Ozon (нужно один
   раз перед первым использованием `/new`).
4. Отправьте `/new` — и пройдите полный диалог создания карточки товара, чтобы
   протестировать весь путь.

Веб-админка (просмотр категорий/товаров/отзывов в браузере) на сервере
специально не открыта в интернет — доступ через туннель:

```bash
# на своей машине (не на сервере!)
ssh -L 8000:localhost:8000 root@ВАШ_IP_АДРЕС
```

Пока туннель открыт — откройте `http://localhost:8000/admin` в браузере на
своём компьютере, войдите логином/паролем из `ADMIN_PANEL_USERNAME`/
`ADMIN_PANEL_PASSWORD`.

## Как посмотреть логи (если что-то работает не так)

```bash
docker compose logs -f bot       # логи Telegram-бота
docker compose logs -f api       # логи backend
docker compose logs -f worker    # логи фоновых задач
docker compose logs --tail=100   # последние 100 строк со всех сервисов
```

`Ctrl+C` — выйти из просмотра логов (сами контейнеры продолжат работать).

## Как обновлять бота в будущем

Когда в коде появятся новые изменения (в репозитории на GitHub):

```bash
cd alicartuning-mp-bot
git pull origin main
docker compose up -d --build
```

Данные (товары, отзывы, история цен) хранятся в volume `pgdata` и переживают
пересборку — ничего не потеряется.

## Если что-то не работает

- **Контейнер в статусе `restarting`** — смотрите его логи
  (`docker compose logs <имя>`), обычно там ошибка вида «не задан токен» или
  «нет доступа к БД». Проверьте `.env`.
- **Бот не отвечает вообще ни на что** — проверьте `TELEGRAM_ADMIN_IDS`
  (ваш ID должен там быть) и что `TELEGRAM_BOT_TOKEN` правильный
  (`docker compose logs bot` покажет, если токен неверный).
- **`docker compose up` ругается на порт занят** — на сервере уже что-то
  висит на 5432/6379/8000; либо остановите это, либо не запускайте `docker
  compose up` дважды подряд без `down`.
- **Нужно полностью остановить бота**: `docker compose down` (данные в
  `pgdata` сохранятся). **Полностью удалить вместе с данными**:
  `docker compose down -v` — используйте осторожно, это необратимо.

## Чек-лист безопасности перед тем, как дать доступ реальным пользователям

- [ ] `TELEGRAM_ADMIN_IDS` содержит только ID тех, кому вы доверяете
- [ ] `API_AUTH_TOKEN` задан случайной строкой (не пусто, не «12345»)
- [ ] `ADMIN_PANEL_PASSWORD` задан и не тривиальный, если пользуетесь `/admin`
- [ ] `.env` не закоммичен в git — проверить: `git status` не должен показывать `.env` как изменённый/новый файл (он в `.gitignore`)
- [ ] Реальные боевые ключи WB/Ozon/Anthropic на месте, а не тестовые заглушки
