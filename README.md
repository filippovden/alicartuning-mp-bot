# ALICARTUNING MP Bot

Telegram AI-менеджер маркетплейсов для магазина **ALICARTUNING** — автоматизирует
создание карточек товаров на Wildberries и Ozon: собирает данные о товаре в диалоге,
генерирует SEO-название/описание через LLM (Claude), проверяет карточку по чек-листу
и публикует товар через API обеих площадок. Также умеет обрабатывать фото, искать
конкурентов, считать аналитику продаж и отвечать на отзывы.

Реализация покрывает MVP + V2 + V3 из технического задания:

| Версия | Функционал | Статус |
|---|---|---|
| MVP | Диалоговый бот, FastAPI backend, PostgreSQL, WB/Ozon Content API, генерация текста через Claude | ✅ |
| V2 | Удаление фона + инфографика, анализ конкурентов, admin-подбор категорий (бот + веб) | ✅ |
| V3 | Аналитика продаж + рекомендация цены, работа с отзывами (автоответы) | ✅ |
| Прод-харденинг | Retry/backoff при 429, веб-админка (SQLAdmin), глобальный whitelist доступа, Redis FSM, 260 тестов (в т.ч. 245+ симулированных сценариев) | ✅ |
| UX для ежедневной выкладки | Постоянное reply-меню, быстрое создание товара (фото + 1 сообщение), прогресс в пошаговом диалоге, `/drafts`, «Опубликовать все» после batch-клонирования, «Цена по рынку» в превью | ✅ |
| Продуктовая полировка | Единый формат превью карточки, «Открыть #ID» вместо технической сетки кнопок, отдельный экран клонирования, /cancel и retry AI-генерации, устойчивость к сбоям API/сети | ✅ |
| Тайминг-аналитика | Тренд цен конкурентов во времени + паттерн спроса по дням недели → когда продвигаться / менять цену | ✅ |

## Исследование open-source аналогов

Перед реализацией V2/V3 изучены существующие открытые реализации похожих ботов и
клиентов, чтобы не изобретать архитектуру с нуля:

- **[AiogramShopBot](https://github.com/ilyarolf/AiogramShopBot)** — открытый
  Telegram-магазин на aiogram 3 + FastAPI + SQLAlchemy async + PostgreSQL + Redis +
  Docker Compose. Стек полностью совпадает с нашим выбором (независимое
  подтверждение архитектуры), и в проекте используется **SQLAdmin** для веб-панели
  администратора — эту идею взяли и подключили (`app/admin.py`) для полноценного
  admin-интерфейса поверх бот-кнопок подбора категории.
- **[wb_tracker_bot](https://github.com/averagepythonfan/wb_tracker_bot)**,
  **[wildberries-notification-bot](https://github.com/PavelShaura/wildberries-notification-bot)** —
  боты на aiogram для отслеживания карточек WB по артикулу; подтверждают
  распространённость связки aiogram + SQLAlchemy для такого рода ботов и
  паттерн «пользователь → подписка → фоновый воркер уведомлений», который мы
  используем в Celery beat для опроса отзывов.
- **[ozon-mcp](https://github.com/PCDCK/ozon-mcp)** — MCP-сервер для Ozon Seller
  API, покрывающий продажи, остатки, цены, финансы и отзывы через Seller API;
  подтвердил, что набор эндпоинтов, который мы уже закрыли (`product/import`,
  `analytics/data`, `review/list`, `products/stocks`, `product/import/prices`),
  соответствует тому, что нужно для полноценного управления кабинетом.
- **Ozon Seller API rate limits** — по документации и открытым обсуждениям Ozon
  при превышении лимита возвращает `429` с телом `{"error_type":
  "rate_limit_exceeded", "retry_after_seconds": N}`. Раньше наши клиенты сразу
  поднимали исключение при любой ошибке; теперь `BaseMarketplaceClient` делает до
  3 повторов с экспоненциальным backoff, уважая это поле (и стандартный заголовок
  `Retry-After`) — см. `app/services/marketplaces/base.py` и
  `tests/test_retry_backoff.py`.
- Отдельных живых Python-SDK для WB/Ozon с нужным нам набором функций (контент +
  статистика + отзывы + аналитика в одном клиенте) в открытом доступе не нашлось —
  большинство репозиториев покрывают только часть API (либо только контент, либо
  только парсинг карточек). Поэтому клиенты в `app/services/marketplaces/`
  написаны самостоятельно по официальной документации, а не форкнуты.

## Архитектура

```
Telegram Bot (aiogram) ──┐
                          ├──> ProductService ──> PostgreSQL
FastAPI backend ─────────┘         │
                                    ├──> AIContentService (Anthropic Claude)
                                    ├──> WildberriesClient / WbStatisticsClient / WbFeedbacksClient
                                    ├──> OzonClient (Seller API: товары, аналитика, отзывы)
                                    ├──> image_pipeline (rembg + Pillow)
                                    └──> competitor_analysis (публичный поиск WB)

Celery + Redis — фоновая публикация, обработка изображений, периодическая
синхронизация категорий Ozon и опрос отзывов (Celery beat).
```

## Быстрый старт (Docker)

1. Скопируйте `.env.example` в `.env` и заполните ключи:

   ```bash
   cp .env.example .env
   ```

   Обязательно укажите:
   - `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather
   - `API_AUTH_TOKEN` — **обязательный секрет для FastAPI backend**, случайная строка
     (например `openssl rand -hex 32`). Все роуты `app/api/routes/` (кроме `/health`)
     требуют заголовок `X-API-Key` с этим значением. **Если оставить пустым — API
     отклоняет все запросы**, тот же fail-closed по умолчанию, что и у
     `TELEGRAM_ADMIN_IDS`: если вы всё же откроете порт `8000` наружу
     (`docker-compose.yml`, по умолчанию не публикуется — см. ниже), без этого
     ключа `/publish/{id}` мог бы дёрнуть кто угодно, кто достучится до порта.
   - `TELEGRAM_ADMIN_IDS` — **обязательный глобальный whitelist доступа**, Telegram ID
     через запятую (например `TELEGRAM_ADMIN_IDS=123456789,987654321`). Бот
     централизованно (см. «Доступ и надёжность» ниже) отклоняет ЛЮБЫЕ входящие
     сообщения от ID вне этого списка. **Если оставить пустым — бот не будет отвечать
     вообще никому**, это осознанный fail-closed по умолчанию, а не баг. Список также
     используется для `/synccategories` и уведомлений о негативных отзывах.
   - `WB_API_KEY` — ключ Wildberries Seller API. **Важно**: с 2023 года WB выдаёт
     JWT-ключи с разным набором категорий доступа (Контент/Статистика/Отзывы и т.д.) —
     для полного функционала бота нужен ключ, включающий категории «Контент»,
     «Статистика» и «Вопросы и отзывы». Ключи в JWT-формате — проверяйте поле `exp`,
     они имеют срок действия (можно раскодировать на [jwt.io](https://jwt.io), не
     передавая его третьим сервисам с реальными секретами).
   - `OZON_CLIENT_ID`, `OZON_API_KEY` — из кабинета продавца Ozon
   - `ANTHROPIC_API_KEY` — ключ Anthropic (для генерации текста карточек и ответов на отзывы).
     `ANTHROPIC_MODEL` (по умолчанию `claude-sonnet-5`) — **перед продом один раз
     проверьте это значение живым ключом**: доступность и точные ID моделей могут
     меняться, а от этой строки зависит вся генерация контента.
   - `ADMIN_PANEL_PASSWORD` — задайте, если нужна веб-админка на `/admin` (см. ниже);
     без пароля панель не поднимается

   ⚠️ **Не публикуйте `.env` и не присылайте API-ключи в открытых чатах/тикетах** —
   файл уже добавлен в `.gitignore`. Если ключ где-то засветился — перевыпустите его
   в кабинете WB/Ozon.

2. Запустите всё через docker-compose:

   ```bash
   docker compose up --build
   ```

   Поднимутся: PostgreSQL, Redis, FastAPI backend (`:8000`, порт наружу не
   публикуется — см. «Доступ и надёжность»), Telegram-бот (polling),
   Celery-воркер и Celery beat (периодические задачи — см. ниже).
   При старте `api`-сервис сам применит миграции (`alembic upgrade head`).

3. Откройте бота в Telegram, отправьте `/start`, затем администратор должен выполнить
   `/synccategories` (наполняет кэш дерева категорий Ozon), после чего можно `/new`.

## Локальный запуск без Docker

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt

# опционально — удаление фона на фото (тяжёлая зависимость, ~250 МБ с моделью):
pip install -r requirements-images.txt

# поднимите PostgreSQL и Redis локально (или через docker compose up postgres redis)
cp .env.example .env   # и поправьте DATABASE_URL/REDIS_URL на localhost

alembic upgrade head

# в одном терминале — backend
uvicorn app.main:app --reload

# в другом — бот
python -m app.bot.main

# опционально — фоновые задачи
celery -A app.worker.celery_app worker --loglevel=INFO
celery -A app.worker.celery_app beat --loglevel=INFO
```

## Команды бота

После `/start` бот показывает постоянное reply-меню (📦 Новый товар / 📋 Мои
товары / 🧬 Клонировать / ⭐ Отзывы / 📊 Аналитика / ⚙️ Ещё) — это основной способ
пользоваться ботом, слэш-команды остаются как power-user путь для тех, кто
предпочитает печатать:

| Команда | Назначение |
|---|---|
| `/start` | приветствие, регистрация пользователя, показывает reply-меню |
| `/new` | создание нового товара: выбор режима «⚡ Быстро» (фото + одно сообщение, AI разбирает текст сам) или «📝 Пошагово» (полная анкета с прогрессом «Шаг N/13») |
| `/drafts` | незаконченные черновики (`status=draft`) с кнопкой «▶️ Продолжить» — возобновляет диалог с первого незаполненного обязательного поля |
| `/list` | список товаров и черновиков, у каждого — кнопки «Клон» / «Пакет» / «Публикация» |
| `/status <ID>` | статус публикации товара и лог попыток |
| `/edit <ID>` | редактирование поля товара (включая артикул/штрихкод/бренд) |
| `/clone <ID>` | клонировать карточку под другую модель авто (см. ниже) |
| `/market <запрос>` | похожие товары конкурентов на Wildberries: цены, ключевые слова (бывш. `/competitors`) |
| `/shop <ссылка на магазин WB>` | разбор магазина-конкурента по ссылке: ассортимент, цены, рейтинг, тренд цены с первого запроса. Только Wildberries — у Ozon нет публичного доступа к чужому каталогу |
| `/analytics` | сводка продаж за 30 дней (WB + Ozon) |
| `/analytics <ID>` | рекомендация цены + тайминг-аналитика: когда продвигаться, когда менять цену |
| `/reviews` | новые отзывы с кнопками автоответа/ручного ответа |
| `/synccategories` | (админ) обновить кэш дерева категорий Ozon |
| `/cancel` | отмена текущего диалога |

Плюс веб-админка на `http://localhost:8000/admin` (см. `ADMIN_PANEL_PASSWORD` в
`.env`) — таблицы категорий, товаров, отзывов и логов публикации в браузере.
При локальном запуске (`docker compose up` на своей машине) открывается сразу.
На сервере порт `8000` по умолчанию не публикуется наружу (см. «Доступ и
надёжность») — доступ через SSH-туннель: `ssh -L 8000:localhost:8000
user@сервер`, затем `http://localhost:8000/admin` в браузере на своей машине.

В превью карточки (после генерации AI-контента) доступны кнопки: «✅
Опубликовать», «🎨 Инфографика», «🖼 Обработать фото», «💰 Цена по рынку» (мин/
средняя/макс цена конкурентов + предложение поставить рекомендованную цену в
один клик), «🔍 Анализ конкурентов», «🧬 Другие модели Lada», «✏️ Править», «❌
Отмена».

## Как это работает

1. **Подбор категории** — при вводе категории бот ищет совпадения через WB API
   (полнотекстовый поиск по имени) и в локальном кэше дерева категорий Ozon
   (`/synccategories`), даёт выбрать нужную кнопками — вместо угадывания по названию.
2. **Диалог `/new`** — бот последовательно спрашивает название, бренд, артикул, цены,
   штрихкод, комплектацию, материал, цвет, габариты, вес и фото. По выбранной
   категории бот подтягивает обязательные характеристики через API WB/Ozon и
   добавляет вопросы по ним динамически.
3. **Генерация контента** — `AIContentService` вызывает Claude по шаблонам промптов
   из раздела 12 ТЗ: SEO-заголовок, описание, буллеты преимуществ, ключевые слова —
   в стиле ALICARTUNING.
4. **Обработка фото (V2)** — `image_pipeline` убирает фон (`rembg`, опционально) и
   вписывает товар в канвас на едином фирменном фоне. Инфографика преимуществ:
   при заданном `XAI_API_KEY` — настоящая AI-генерация изображения через **xAI
   Grok Imagine** (`app/services/ai/grok_imagine.py`) по промпту, собранному из
   буллетов Claude (белый/светло-серый фон, товар по центру, 3 преимущества с
   ✓-иконками, бренд, акцент на совместимость с Lada, без рекламной лексики);
   без ключа или при сбое API — fallback на прежний MVP-рендер (Pillow,
   текстовые слои с буллетами на фирменном фоне), бот не падает. Ключ — на
   [console.x.ai](https://console.x.ai), ориентировочная стоимость $0.02–0.05
   за изображение (актуальные цены смотрите там же).
5. **Анализ конкурентов (V2)** — поиск похожих карточек на WB через публичный API
   витрины, средняя цена, популярные слова в названиях. Для Ozon нет официального
   публичного поиска по каталогу — функция явно сообщает об этом ограничении
   (см. ниже), а не возвращает фиктивные данные.
6. **Валидация** — перед публикацией `validate_product()` проверяет карточку по
   чек-листу (обязательные поля, длина текста, запрещённые слова, фото, числа,
   уникальность SKU) и выводит список проблем, если карточка не готова.
7. **Публикация** — `ProductService.publish()` формирует запросы через `mapping.py`
   (раздел 9 ТЗ) и вызывает `WildberriesClient.create_card()` и
   `OzonClient.import_products()`, результат сохраняется в `PUBLISH_LOGS`.
8. **Аналитика и цены (V3)** — `analytics_service` тянет продажи из WB Statistics API
   и Ozon Analytics API, агрегирует по SKU и считает рекомендованную цену
   (себестоимость + целевая маржа, скорректированная по среднему чеку конкурентов).
9. **Тайминг-аналитика (когда продвигаться / менять цену)** — `pricing_intelligence`
   решает более узкую задачу, чем разовая цена: копит историю цен конкурентов
   (`CompetitorPriceSnapshot`, снимок раз в сутки через Celery beat + опортунистически
   при каждом `/analytics <ID>`) и сопоставляет тренд («цены конкурентов растут/
   падают/стабильны за последние 30 дней») с паттерном спроса по дням недели из
   реальных продаж WB. На выходе — конкретная рекомендация: держать/снижать/
   поднимать цену сейчас, или вкладываться в продвижение, плюс лучший день недели
   для старта рекламной кампании. Без достаточной истории (< 3 снимков) честно
   сообщает об этом, а не выдумывает тренд на пустых данных. После ежедневного
   снимка та же Celery-задача сразу проверяет, не стал ли тренд по какому-то
   товару значимым, и шлёт админам дайджест — не нужно самому вспоминать зайти
   и посмотреть `/analytics`.
10. **Отзывы (V3)** — `review_service` синхронизирует неотвеченные отзывы (WB Feedbacks
    API, Ozon Reviews API), классифицирует тональность по оценке и либо генерирует
    AI-ответ в фирменном тоне, либо позволяет ответить вручную. Celery beat раз в час
    опрашивает отзывы и уведомляет админов в Telegram о новых негативных.
11. **Клонирование под другую модель авто** (`ProductService.clone_product`,
    `app/bot/handlers/clone_product.py`) — одна деталь автотюнинга часто подходит
    сразу нескольким моделям Lada, и проще размножить карточку, чем заполнять с
    нуля. `/clone <ID>` или кнопка «🧬 Создать похожую» (в `/list` и в превью)
    копируют категорию/бренд/материал/цвет/комплектацию/габариты/вес/цену/фото/
    характеристики (`Attribute`); артикул, штрихкод, название, описание и ID
    уже опубликованной карточки-источника (`wb_nm_id`/`ozon_product_id`) НЕ
    копируются. Диалог сразу спрашивает новую модель авто, затем новый
    уникальный артикул — только после этого генерируется текст и показывается
    превью с кнопкой «Опубликовать» (без артикула кнопка не появляется, чтобы
    нельзя было отправить публикацию без обязательного поля). Превью явно
    показывает `Артикул: … / Модель: …`, чтобы карточки было видно, что они
    разные. Кнопка «📦 Сделать для нескольких моделей» принимает список моделей
    через запятую (до 5), затем — шаблон артикула вида `ART-{model}`
    (`{model}` подставляется в верхнем регистре без пробелов; если шаблон
    пропущен — артикул генерируется автоматически как `ART-CLONE-{id}`), и в
    конце показывает сводку с артикулом/моделью каждого черновика и кнопками
    публикации — плюс кнопка «✅ Опубликовать все» (`app/bot/handlers/new_product.publish_all`),
    публикующая все созданные черновики последовательно одним отчётом.
12. **Быстрое создание товара** (`app/bot/handlers/quick_create.py`) — основной
    сценарий ежедневной выкладки вместо анкеты из 13 шагов: пользователь
    присылает от 3 фото и ОДНИМ сообщением произвольное описание («Накладки
    зеркал BMW-стиль, Lada Granta, ABS, чёрный глянец, цена 990»).
    `AIContentService.parse_quick_description` разбирает текст в JSON (тип
    детали, модель, материал, цвет, цена, комплектация, при наличии — размеры
    и вес), бот сам подбирает категорию WB/Ozon по типу детали (без
    интерактивного выбора) и генерирует title/description через AI, а
    спрашивает только то, что не удалось угадать: артикул — всегда (он
    обязателен и должен быть уникальным), размеры/вес — если их не было в
    тексте. Итоговый чеклист явно показывает, что уже готово и чего не хватает,
    перед превью с теми же кнопками, что и у пошагового режима.
13. **Статус модерации WB (заготовка)** — раз в ~45 минут Celery beat-задача
    `check_wb_card_status` (`app/worker/celery_app.py`,
    `ProductService.check_wb_card_status`) опрашивает `/get/cards/list` по уже
    опубликованным карточкам и шлёт админам уведомление при изменении
    видимости карточки в каталоге. Это best-effort эвристика (WB Content API
    не отдаёт отдельного поля «одобрено/отклонено» в этом эндпоинте) — честно
    задокументирована как заготовка, а не выдаётся за полноценную проверку
    причин отклонения.
14. **Разбор магазина-конкурента по ссылке (`/shop`)** — в отличие от `/market`
    (поиск похожих товаров по ключевому слову), `/shop <ссылка на магазин WB>`
    достаёт ID продавца из ссылки (`wildberries.ru/seller/<ID>`) и собирает
    ВЕСЬ ассортимент магазина через `catalog.wb.ru/sellers/catalog?supplier=<ID>`
    (тот же неофициальный публичный API витрины, что и у `/market`) — товары,
    цены, средний рейтинг, суммарное число отзывов. Каждый запрос сохраняет
    снимок (`ShopSnapshot`), а Celery beat (`snapshot_tracked_shops`, раз в сутки)
    сам обновляет данные по уже запрошенным магазинам, поэтому тренд цены
    появляется постепенно — не нужно вручную дёргать `/shop` каждый день.
    **Только Wildberries**: у Ozon Seller API нет доступа к чужому каталогу, а
    сайт Ozon отдаёт данные через тяжёлый JS, который нельзя стабильно
    распарсить без headless-браузера — команда явно объясняет это
    пользователю, а не притворяется, что Ozon поддерживается. Ретроактивной
    истории цен по чужому магазину не бывает нигде — данные копятся только с
    момента первого запроса.

## Доступ и надёжность

- **Глобальный whitelist доступа** — `AccessControlMiddleware`
  (`app/bot/middlewares.py`) подключён как outer-middleware в `app/bot/main.py` и
  проверяет **каждый** входящий `Update` (сообщения, callback-кнопки, любые другие
  типы), а не только команды в admin-хендлерах. Пропускает только
  `telegram_id ∈ settings.telegram_admin_id_list`; если список пуст — отказывает
  всем без исключений (fail-closed по умолчанию, см. `TELEGRAM_ADMIN_IDS` выше).
  Неавторизованным — «Доступ запрещён» (алертом на callback, сообщением на прочее).
- **FSM-хранилище — Redis, не память** — `app/bot/main.py` использует
  `RedisStorage.from_url(settings.redis_url)` вместо `MemoryStorage`. Состояние
  диалога `/new` (на каком шаге пользователь, что уже введено) переживает рестарт
  контейнера бота — раньше при деплое/падении контейнера все незавершённые диалоги
  обнулялись.
- **Публикация в WB — сначала карточка, потом фото** — `ProductService._publish_to_wb`
  учитывает, что `POST /cards/upload` создаёт карточку асинхронно и не возвращает
  настоящий `nmID` сразу. Сервис опрашивает `POST /get/cards/list` (до 5 попыток с
  паузой) и только после подтверждения `nmID` вызывает `POST /cards/upload/images`.
  Любая ошибка на каждом из шагов (создание карточки, неподтверждённый `nmID`,
  отсутствие публичных URL фото при локальном хранилище, сбой загрузки фото)
  возвращает понятный текст пользователю в Telegram, а не тихо проглатывается.
- **Минимум 3 фото** — кнопку «Готово» на шаге фото (`photos_done` в
  `app/bot/handlers/new_product.py`) нельзя нажать, пока не загружено
  `MIN_PRODUCT_PHOTOS` (3) фото; бот сообщает, сколько ещё нужно добавить.
- **Ozon: `vat` и `type_id`** — `build_ozon_item` (`app/services/marketplaces/mapping.py`)
  всегда передаёт обязательное поле `vat` (по умолчанию `OZON_DEFAULT_VAT` из `.env`,
  можно переопределить точечно) и `type_id` вместе с `category_id` — Ozon с 2022 года
  требует оба поля для двухуровневой категоризации, без `type_id` запрос отклоняется.
  Если у категории задан только `ozon_category_id` без `ozon_type_id` (например,
  недонастроена в `/admin`), `_publish_to_ozon` ловит это до реального запроса и
  возвращает понятную ошибку вместо непрозрачного отказа Ozon API.
- **Ozon: fail-closed `_is_admin`** — `app/bot/handlers/admin.py` симметричен
  `AccessControlMiddleware`: пустой `TELEGRAM_ADMIN_IDS` не даёт доступа никому, а не
  всем (раньше было наоборот — маскировалось тем, что до хендлера уже не пропускал
  outer-middleware, но при любом изменении порядка middleware стало бы дырой).
- **Конкурентный анализ не путает карточку продавца с конкурентами** —
  `search_wb_competitors` (`app/services/competitor_analysis.py`) принимает
  `exclude_brand` и отфильтровывает товары с этим брендом из выдачи WB. После
  публикации карточка ALICARTUNING нередко сама попадает в поиск по своему же
  названию/модели — без фильтрации «средняя цена конкурентов» начинала включать
  собственную цену продавца, схлопывая сигнал в обратную связь с самим собой.
- **Проактивные уведомления о трендах цен** — раньше тренд цен конкурентов был
  виден только вручную через `/analytics <ID>`. Теперь ежедневная Celery-задача
  `snapshot_competitor_prices` после снятия снимков сама проверяет тренд
  (`check_significant_price_trends`) и, если по какому-то товару он уже значимый
  (рост/падение свыше `TREND_SIGNIFICANT_PCT`), шлёт админам один дайджест —
  не нужно вспоминать зайти и проверить самому.
- **FastAPI backend требует `X-API-Key`, порт наружу не публикуется** — по
  итогам security-review выяснилось, что `app/api/routes/products.py` и
  `admin.py` были полностью открыты: без единого ключа можно было дёргать
  `/publish/{id}` (реальная публикация на WB/Ozon чужими сохранёнными ключами
  магазина) и `/saveDraft` (IDOR — правка любого товара по перебору
  `product_id`), а `docker-compose.yml` публиковал порт 8000 на хост. Теперь
  `require_api_token` (`app/api/deps.py`) требует заголовок `X-API-Key`,
  подключён на уровне роутера через `dependencies=[...]` (нельзя забыть на новом
  роуте), fail-closed при пустом `API_AUTH_TOKEN`; `/health` осознанно оставлен
  открытым (health-check без чувствительных данных). Плюс `docker-compose.yml`
  теперь по умолчанию вообще не публикует порты `postgres`/`redis`/`api` на
  хост (бот работает с БД напрямую, backend ему не нужен) — раскомментируйте
  `ports:` только если реально нужен внешний доступ к API.
- **Отзывы: экранирование HTML** — `review.text` приходит из публичных отзывов
  WB/Ozon (недоверенный ввод — пишет любой покупатель), а бот шлёт сообщения с
  `parse_mode=HTML` по умолчанию. Без экранирования отзыв с разметкой вроде
  `<a href="...">` рендерился бы кликабельной ссылкой в чате админа (фишинг под
  видом внутреннего инструмента). `_format_review` и подтверждение авто-ответа
  (`app/bot/handlers/reviews.py`) теперь экранируют текст через `html.escape()`.
- **Админка: сравнение пароля за постоянное время** — `AdminAuth.login()`
  (`app/admin.py`) сравнивает логин/пароль через `secrets.compare_digest` вместо
  `==`, чтобы не давать теоретическую возможность timing-атаки на пароль.

## Известные ограничения

- **Поиск конкурентов на Ozon не реализован** — Ozon Seller API не предоставляет
  доступа к чужим карточкам каталога. Для этой функции понадобится либо парсинг
  витрины Ozon (нестабильный неофициальный способ), либо платный сторонний сервис
  аналитики (MPStats, Moneyplace и т.п.) со своим API-ключом.
- **Поиск конкурентов на WB** использует неофициальный публичный API витрины
  (`search.wb.ru`) — он не документирован для продавцов и может измениться без
  предупреждения; обёрнут в обработку ошибок, но не гарантирован SLA. По той же
  причине **тайминг-аналитика цен** (`pricing_intelligence.py`) наследует это
  ограничение — она строится на снимках того же источника.
- **Тайминг-аналитика требует накопленной истории** («холодный старт»): тренд цен
  считается минимум по 3 суточным снимкам (Celery beat, `snapshot_competitor_prices`,
  плюс опортунистический снимок при каждом `/analytics <ID>`), а паттерн спроса по
  дням недели — минимум по 5 дням с продажами за 60 дней. Пока данных недостаточно,
  бот честно об этом сообщает вместо того, чтобы придумывать тренд из одной точки.
- **Удаление фона** (`rembg`) — тяжёлая опциональная зависимость
  (`requirements-images.txt`, ~250 МБ с ONNX-моделью U²-Net). При первом запуске
  требует скачивания модели из интернета; без неё пайплайн работает в режиме
  no-op (вписывает фото в шаблон без удаления фона), бот не падает.
- **WB API-ключи с 2023 года выдаются по категориям доступа** (Контент, Статистика,
  Цены и скидки, Вопросы и отзывы и т.д.) — один ключ может не покрывать все функции
  бота (создание карточек, аналитику, отзывы). Если часть команд отвечает ошибкой
  авторизации — проверьте, какие категории доступа включены в выпущенный ключ.
- **Хранилище файлов: локальный диск по умолчанию, S3 — при настройке**
  (`app/services/storage.py`). По умолчанию (`STORAGE_BACKEND=local`)
  `StorageFile.url` — это путь на диске контейнера, а не публичный http(s)-адрес,
  поэтому WB (см. «Доступ и надёжность» выше) физически не может скачать по нему
  фото — публикация карточки пройдёт успешно, но `PublishLog.message` честно
  сообщит, что фото не загружены. Если задать `STORAGE_BACKEND=s3` и заполнить
  `S3_ENDPOINT_URL`/`S3_BUCKET`/`S3_ACCESS_KEY`/`S3_SECRET_KEY`, файл
  дополнительно заливается в S3-совместимое хранилище (AWS S3, MinIO,
  Selectel/Timeweb/Yandex Object Storage и т.п. — любой S3 API) через `boto3`,
  и `url` становится реальным публичным HTTPS-адресом; `path` при этом всегда
  остаётся локальным (внутренние обработчики вроде `image_pipeline` продолжают
  читать файл с диска). Для продакшена такая настройка обязательна.
- Массовая загрузка через CSV/Excel/1С (раздел 13, Этап 3) не реализована — это
  единственный крупный нереализованный пункт дорожной карты ТЗ; веб-админка
  (SQLAdmin, `/admin`) для ручного подбора категорий и просмотра данных уже есть.
- Симуляции в `tests/test_simulations.py` гоняются на SQLite in-memory и моках
  внешних API — это регрессионный прогон бизнес-логики и кода хендлеров бота, а не
  нагрузочное или E2E-тестирование против реальных WB/Ozon; перед продакшеном
  стоит дополнительно прогнать сценарии на тестовых аккаунтах WB/Ozon (если/когда
  площадки предоставят sandbox).
